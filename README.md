## Доменный слой

### User 

- У пользователя должен быть ID
- У пользователя должно быть имя (len > 0)
- У пользователя должен быть платежный счет 
- У пользователя должна быть корзина
- У пользователя должен быть профиль
- У пользователя должна быть история заказов 

### UserAuth

- У UserAuth должен быть ID 
- У UserAuth должен быть UserID
- У UserAuth должен быть тип, определяющий провайдера авторизации 
- UserID может быть не уникальным - разные провайдеры авторизации реализуются путем добавления новой записи UserAuth
- Должна быть возможность бесполезненно добавлять различных провайдеров авторизации
- Авторизация должна реализовываться через JWT (Access + Refresh) токены 

### Account 

- У счета должен быть ID 
- У счета должен быть тип (Hold | System | User)
- Допускается что системный счет может быть один на все приложение на данный момент
- У счета должен быть OwnerID (для Hold-счета это User-счет, для User-счета это User, у System допускается dummy-значение на owner-id)
- У счета должен быть Balance типа Decimal 
- Счет должен поддерживать операции Debit (списание) и Credit (пополнение). Переводы реализуются на сервисном слое 
- У счета должен быть указан конкретный тип валюты (пока допускается денормализованное представление из Symbol: string)
- У любой операции со счетом должна быть зеркальная на другом счету (Debit = Credit)

### LedgerEntry 

Все операции производимые со счетами должны записываться в append-only таблицу бухгалтерского учета 

- У записи должен быть ID
- У записи должен быть AccountID 
- У записи должен быть тип операции (DEBIT | CREDIT)
- У записи должен быть указан тип валюты
- У записи должен быть timestamp, не зависящий от тайм-зоны

### Product

- У товара должен быть ID
- У товара должна быть цена
- У товара должно быть название
- У товара должны быть изображения Thumbnails (JSON/Служебная таблица ProductThumbnails)
- У товара должна быть скидка в процентах Discount, 0 <= Discount < 1
- DiscountedCost не материализуется, а вычисляется по запросу (для консистентности)
- У товара должна быть категория 
- У товара должен быть набор атрибутов различных типов, соответствующий его категории

### Category

- У категории должен быть ID 
- Категории могут быть вложенными, Nullable ParentCategoryId
- У категории должно быть название
- Поиск по категории должен возвращать продукты дочерних категорий в том числе
- Категория должна определять набор допустимых атрибутов для продуктов 

### ShoppingCart

- У ShoppingCart должен быть ID 
- ShoppingCart уникальна для каждого пользователя

### ShoppingCartEntry

- У ShoppingCartEntry должен быть ShoppingCartID
- У ShoppingCartEntry должен быть ProductID
- У ShoppingCartEntry должен быть Amount

### Order

- У заказа должен быть статус (Created -> Purchased -> Completed | Cancelled)
- Невозможно изменить статус заказа с Cancelled на любой другой
- Невозможно перейти из любого статуса кроме Created в Created
- У заказа должен быть ID
- У заказа должен быть Timestamp
- Заказ должен хранить снапшоты товаров на время Timestamp (для аудита)
- У заказа должна быть сумма
- У заказа должен быть UserID
- Completed | Cancelled заказы неизменяемы
- Заказ создается из корзины
- У заказа должен быть ShippingAdress

### OrderStatusHistory

Изменения статуса заказа должны записываться

- У OrderStatusHistory должен быть ID
- У OrderStatusHistory должен быть Cause
- У OrderStatusHistory должен быть Timestamp
- У OrderStatusHistory должен быть OrderID
- У OrderStatusHistory должен быть FromStatus
- У OrderStatusHistory должен быть ToStatus

### OrderEntry

- У OrderEntry должен быть ID
- У OrderEntry должен быть ProductID для аналитики 
- У OrderEntry должна быть цена
- У OrderEntry должно быть название
- У OrderEntry должно быть количество Quantity
- У OrderEntry должна быть скидка в процентах Discount, 0 <= Discount < 1
- DiscountedCost для OrderEntry материализуется

### WareHouseEntry

- У WareHouseEntry должен быть ID 
- У WareHouseEntry должен быть ProductID
- У WareHouseEntry должен быть Amount, Amount >= 0 
- У каждого Product должен быть WareHouseEntry

- Насколько информативные ошибки стоит возвращать клиенту?

UPD: скорее всего введу 3-4-5 видов ошибок отдаваемых клиенту:
